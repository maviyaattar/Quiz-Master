1. Project Overview

What is Quiz Master?

Quiz Master is a comprehensive online quiz platform that enables educators and organizations to create, manage, and conduct quizzes efficiently. The platform offers both manual and AI-powered quiz creation, real-time quiz management, and detailed analytics.

Key Features

🎯 Quiz Creation

Create quizzes manually or use AI to generate questions automatically from topics

⚡ Real-time Management

Start, monitor, and end quizzes in real-time with live participant tracking

📊 Analytics & Results

Comprehensive results dashboard with participant scores, rankings, and PDF export

🔒 Security Features

Anti-cheat mechanisms including tab-switch detection and time-bound assessments

🎨 Custom Branding

Upload organization logos and customize quiz appearance

📱 Responsive Design

Works seamlessly across desktop, tablet, and mobile devices

User Roles

  • Quiz Creator: Registered users who can create, manage, and analyze quizzes
  • Participant: Anyone with a quiz code can join and attempt quizzes (no registration required)

Frontend Architecture

The frontend is built using vanilla JavaScript with a modular approach:

  • HTML5: Semantic markup for structure
  • CSS3: Custom stylesheets with CSS variables for theming
  • JavaScript (ES6+): Modern JavaScript for interactivity and API communication

Backend Architecture

RESTful API built with Node.js and Express:

  • Route Handlers: Organized by feature (auth, quiz, results)
  • Middleware: Authentication, validation, error handling
  • Database Layer: Mongoose ODM for MongoDB operations

8. Key Features Explanation

User Authentication (JWT-based)

How it works:

  1. User submits login/register form
  2. Backend validates credentials and hashes password (bcryptjs)
  3. Backend generates JWT token with user ID payload
  4. Token sent to frontend and stored in localStorage
  5. All protected API requests include token in Authorization header
  6. Backend middleware verifies token on each request
// Example: Using JWT token
const response = await fetch('${API}/api/quiz/my', {
  headers: {
    'Authorization': 'Bearer ' + localStorage.getItem('token')
  }
});

Quiz Creation: Manual vs AI Mode

Manual Mode

Traditional approach where creators add questions one by one:

  • Fill in question text
  • Add 4 multiple-choice options
  • Select correct answer
  • Questions stored in array and can be edited/deleted
  • Preview questions before submission

AI Mode (OpenAI Integration)

Automated question generation:

  • User provides: Topic, Number of questions, Difficulty level
  • Backend sends structured prompt to OpenAI API
  • AI generates questions in required JSON format
  • Questions parsed and validated on backend
  • Frontend receives and displays for review
  • Creator can edit AI-generated questions before saving

Real-time Quiz Joining: Polling Mechanism

Since WebSockets aren't used, the app implements polling:

  1. Participant joins with code and enters wait screen
  2. Frontend polls /api/quiz/join/:code every 3-5 seconds
  3. Checks if quiz status changed from "created" to "live"
  4. When live, quiz questions are loaded and timer starts
  5. This simulates real-time without WebSocket complexity

Quiz Attempt Flow

Timer Implementation

// Timer decrements every second
let timeLeft = quizDuration * 60; // Convert minutes to seconds
const timerInterval = setInterval(() => {
  timeLeft--;
  updateTimerDisplay();
  
  if (timeLeft <= 0) {
    clearInterval(timerInterval);
    autoSubmitQuiz(); // Force submit
  }
}, 1000);

Question Navigation

  • Questions displayed one at a time
  • Previous/Next buttons for navigation
  • Answers stored in array (index-based)
  • Visual indicator for answered questions
  • Can change answers before submission

Anti-Cheat: Tab Switch Detection

// Detect when user leaves the quiz tab
document.addEventListener('visibilitychange', () => {
  if (document.hidden) {
    warnings++;
    showWarning('Tab switching detected! Warning ' + warnings);
    // Warnings included in submission
  }
});

Results & Analytics

Score Calculation

// Backend calculates score
let correctCount = 0;
submission.answers.forEach((answer, index) => {
  if (answer === quiz.questions[index].correctIndex) {
    correctCount++;
  }
});

const score = correctCount;
const total = quiz.questions.length;
const percentage = (score / total) * 100;

Leaderboard/Ranking

  • All submissions sorted by score (descending)
  • Rank assigned based on position
  • Ties handled by submission time (earlier is better)
  • Search and filter by name/roll number

Logo Upload (Cloudinary Integration)

  1. User selects image file
  2. File sent to backend via multipart/form-data
  3. Multer middleware processes file upload
  4. Backend uploads to Cloudinary (cloud storage)
  5. Cloudinary returns secure URL
  6. URL saved with quiz data and displayed on attempt page

PDF Export (PDFKit)

Backend generates PDF certificates for participants:

  • Uses PDFKit library to create PDF documents
  • Includes quiz name, participant details, score
  • Can include organization logo if uploaded
  • PDF sent as blob to frontend
  • Frontend triggers download

9. Security Implementations

Input Sanitization

All user inputs are sanitized to prevent XSS attacks:

function sanitizeInput(input) {
  const div = document.createElement('div');
  div.textContent = input; // Automatically escapes HTML
  return div.innerHTML;
}

// Usage
const safeName = sanitizeInput(userInput);

XSS Prevention

  • All user-generated content escaped before display
  • Using textContent instead of innerHTML where possible
  • Server-side validation and sanitization
  • Content Security Policy headers on backend

CSRF Protection

  • JWT tokens in Authorization headers (not cookies)
  • SameSite cookie attributes if cookies used
  • Origin checking on backend

Password Security

// Backend hashing with bcryptjs
const salt = await bcrypt.genSalt(10);
const hashedPassword = await bcrypt.hash(password, salt);

// Verification
const isMatch = await bcrypt.compare(inputPassword, storedHash);

JWT Token Security

  • Tokens signed with secret key
  • Expiration time set (typically 7 days)
  • Tokens verified on each protected route
  • Token payload minimal (only user ID)
  • Stored in localStorage (consider httpOnly cookies for production)

API Security Measures

  • Rate limiting on authentication endpoints
  • Input validation with Joi/express-validator
  • Error messages don't leak sensitive info
  • CORS configured for specific origins
  • HTTPS enforced on production

Database Security

  • MongoDB connection string in environment variables
  • No raw queries (using Mongoose ODM)
  • Input validation before database operations
  • Sensitive data encrypted at rest

10. Database Schema (MongoDB)

Creator Collection

{
  _id: ObjectId,
  name: String,
  email: String (unique, indexed),
  password: String (hashed),
  createdAt: Date,
  updatedAt: Date
}

Quiz Collection

{
  _id: ObjectId,
  code: String (unique, indexed, 6-char alphanumeric),
  creator: ObjectId (ref: Creator),
  title: String,
  description: String,
  duration: Number (minutes),
  questions: [
    {
      text: String,
      options: [String, String, String, String],
      correctIndex: Number (0-3)
    }
  ],
  status: String (enum: 'created', 'live', 'ended'),
  orgName: String (optional),
  logoUrl: String (optional),
  createdAt: Date,
  updatedAt: Date
}

Submission Collection

{
  _id: ObjectId,
  quiz: ObjectId (ref: Quiz),
  name: String,
  rollNo: String (indexed),
  branch: String,
  answers: [Number] (array of selected option indices),
  score: Number,
  totalQuestions: Number,
  percentage: Number,
  warnings: Number (tab switches),
  submittedAt: Date
}

Indexes

  • Creator.email: Unique index for fast lookups
  • Quiz.code: Unique index for quiz code searches
  • Quiz.creator: Index for fetching user's quizzes
  • Submission.quiz: Index for fetching quiz results
  • Submission.rollNo: Index for participant searches

async function fetchUserQuizzes() {

async function performAction() {
  const button = event.target;
  
  // Disable button during operation
  button.disabled = true;
  button.textContent = 'Loading...';
  
  try {
    const response = await fetch(`${API}/api/endpoint`, {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json',
        'Authorization': 'Bearer ' + localStorage.getItem('token')
      },
      body: JSON.stringify(data)
    });
    
    const result = await response.json();
    
    if (!response.ok) {
      // Handle specific error codes
      if (response.status === 401) {
        // Unauthorized - redirect to login
        localStorage.removeItem('token');
        location.href = 'auth.html';
        return;
      }
      
      throw new Error(result.msg || 'Operation failed');
    }
    
    // Success
    showSuccess('Operation completed successfully!');
    
  } catch (error) {
    console.error('Error:', error);
    showError(error.message || 'An unexpected error occurred');
  } finally {
    // Re-enable button
    button.disabled = false;
    button.textContent = 'Submit';
  }
}

function renderQuizCards(quizzes) {
  const container = document.getElementById('quizGrid');
  
  // Clear existing content
  container.innerHTML = '';
  
  if (quizzes.length === 0) {
    container.innerHTML = `
      

        
No quizzes found

        
Create your first quiz to get started!

      

    `;
    return;
  }
  
  // Create cards for each quiz
  quizzes.forEach(quiz => {
    const card = document.createElement('div');
    card.className = 'quiz-card';
    card.onclick = () => openQuiz(quiz.code);
    
    // Sanitize content
    const safeTitle = sanitizeHTML(quiz.title);
    const safeDesc = sanitizeHTML(quiz.description);
    
    card.innerHTML = `
      
${safeTitle}

      
${safeDesc}

      
        ${quiz.status.toUpperCase()}
      
    `;
    
    container.appendChild(card);
  });
}

function sanitizeHTML(str) {
  const div = document.createElement('div');
  div.textContent = str;
  return div.innerHTML;
}

// Save data
function saveToLocalStorage(key, value) {
  try {
    const jsonString = JSON.stringify(value);
    localStorage.setItem(key, jsonString);
  } catch (error) {
    console.error('Error saving to localStorage:', error);
  }
}

// Retrieve data
function getFromLocalStorage(key, defaultValue = null) {
  try {
    const item = localStorage.getItem(key);
    return item ? JSON.parse(item) : defaultValue;
  } catch (error) {
    console.error('Error reading from localStorage:', error);
    return defaultValue;
  }
}

13. Best Practices Used

Code Organization

  • Separation of Concerns: Each page has its own JavaScript file
  • Modular CSS: Page-specific stylesheets with shared base styles
  • Consistent Naming: camelCase for JS variables/functions, kebab-case for CSS classes
  • File Structure: Organized by type (js/, css/, html files in root)

Error Handling Patterns

  • Try-Catch Blocks: All async operations wrapped in try-catch
  • User Feedback: Clear error messages displayed to users
  • Graceful Degradation: App continues working even if non-critical features fail
  • Console Logging: Errors logged to console for debugging (should be removed in production)

Async/Await Usage

  • Preferred over promise chains for readability
  • Always include try-catch for error handling
  • Proper use of await for sequential operations
  • Parallel operations with Promise.all when appropriate

Input Validation

  • Client-Side: Immediate feedback, better UX
  • Server-Side: Security layer, never trust client
  • Sanitization: All inputs sanitized before display or storage
  • Type Checking: Validate data types and formats

Responsive Design Principles

  • Mobile-first approach
  • Flexbox and Grid for layouts
  • Media queries for different screen sizes
  • Touch-friendly interface elements
  • Readable font sizes on all devices

Performance Optimization

  • Minimize DOM Manipulation: Batch updates where possible
  • Cache DOM Queries: Store frequently accessed elements
  • Debounce Search: Wait for user to finish typing
  • Lazy Loading: Load data only when needed
  • Image Optimization: Use Cloudinary for automatic optimization

Security Best Practices

  • All user input sanitized
  • Passwords never stored in plain text
  • JWT tokens for authentication
  • HTTPS enforced in production
  • Rate limiting on sensitive endpoints
  • CORS properly configured

Code Comments

  • Function documentation with JSDoc-style comments
  • Section dividers for organization
  • Inline comments for complex logic
  • TODO comments for future improvements
